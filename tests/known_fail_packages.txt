# Multi-package fixtures that don't build (or don't answer right) yet, and the
# issue tracking each. One name per line — the directory under tests/packages/.
# `#` comments ignored.
#
# The gate reports a fixture that starts working, so a fix can't be made and
# left unrecorded.
#
# Every one of these is the same root: `check_package` flattens a dependency's
# public declarations into the root's and renames each through `prefix_decl`,
# which renames the declaration's own name and nothing that refers to it — and
# then pushes a *second*, unprefixed copy when the consumer imported the name,
# giving the type two declarations and two TypeIds.

constructor              # #1112 — a package can't export a function that
                         # constructs its own struct. Declaring one breaks every
                         # consumer, called or not.
const-export             # #1123 — an exported `const` reads as 0. Builds fine;
                         # the answer is just wrong, for an i64 and a string
                         # alike.
method-export            # #1124 — a method on an exported struct isn't found.
                         # The `extend` block attaches to the prefixed type.
vec-return               # #1125 — a function returning `Vec<T>` loses its type
                         # across the boundary; `v.len()` fails MIR dispatch.
                         # A `string` return is fine.
enum-export              # #1126 — `import libpkg.Colour` is reported as
                         # "`Colour` is a built-in type". It isn't; the duplicate
                         # copy collides and BI2's check is what notices.
