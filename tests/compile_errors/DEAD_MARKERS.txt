# Markers in tests/compile_errors/ that no diagnostic answers.
#
# Every `// ERROR` line in that directory claims the compiler rejects the code
# below it. `compile_error()` only ever checked that the file failed *somewhere*,
# so a marker whose rule had never been implemented — or had stopped firing —
# looked exactly like one that worked. 13 of 328 turned out to answer nothing.
#
# The gate now anchors each marker to a line: a marker must be followed by a
# diagnostic before the next marker. The counts below are the ones still
# outstanding. They go DOWN on their own — the test fails if a file grows a new
# dead marker, and fails if a count here is too high, so a fix can't be made and
# left unrecorded.
#
# A count going UP needs a reason in the commit, and there is only one good one:
# a diagnostic that was answering the marker by accident has been removed, so a
# claim nobody was checking becomes visible. That has happened twice — fixtures
# that had forgotten `mut` on their own locals, reporting `E0322 cannot mutate —
# declared let` over the rules they meant to test; and a helper in
# `match_errors.rk` that leaked its own `take` parameter, whose E0805 was
# standing in for a non-exhaustive-match claim two functions above it.
#
# That last one is this check's blind spot: it asks whether *a* diagnostic lands
# under the marker, not whether it is the right one. Only 65 of the markers name
# a code, so that is as far as it can go on its own. Keeping one rejection per
# section, with the marker on the line the compiler points at, is what keeps the
# blind spot small.
#
# Two ways off this list. Either the rule is real and the marker should fire, in
# which case the compiler needs the check (that is the interesting case — see
# audit 1.3 for two rules found unenforced this way). Or the marker is wrong and
# should go, usually because it sits below a parse error that stops the pipeline
# before the checker ever runs (see audit 1.2).
#
# Nothing is left. #1088 is done: an argument that reaches the same storage as
# another argument of the same call, where one of them writes, is E0870; binding
# a non-Copy element out of a collection is E0871; returning a borrowed
# parameter's non-Copy field is E0872; and `mut x = value.field` on a non-Copy
# field is E0873. The fifth marker was a fixture bug — `Player` is 8 bytes, so
# `let stored = p` copied it and the rule it claimed (moving out of a borrow)
# was already enforced for everything the copy threshold doesn't cover.
# #1089 is done: a public function that reads through a handle must name its
# pool (E0867), a pool context that reaches a public function or the entry point
# with nowhere left to come from is rejected there instead of segfaulting
# (E0868), and a structural call through an unnamed `using` clause says the
# clause binds nothing rather than suggesting a spelling fix (E0869). Two of
# those four fixtures also had bugs of their own that stopped the pipeline
# before the context pass ran, and two carried a second `// ERROR` header for a
# rejection their inline marker already anchored — the second kind, removed.
# #1090 is done: break-with-value from `while` is E0865, a `match` expression
# over an integer with no arm for the rest is E0864, a `value.(comptime …)`
# block that answers with something other than a name is E0866, and one that
# runs past its branch quota is E0383 — the evaluator runs at check time now,
# not only at MIR.
#
# Format: <file> <count of dead markers>
