# Markers in tests/compile_errors/ that no diagnostic answers.
#
# Every `// ERROR` line in that directory claims the compiler rejects the code
# below it. `compile_error()` only ever checked that the file failed *somewhere*,
# so a marker whose rule had never been implemented — or had stopped firing —
# looked exactly like one that worked. 41 of 354 turned out to answer nothing.
#
# The gate now anchors each marker to a line: a marker must be followed by a
# diagnostic before the next marker. The counts below are the ones still
# outstanding. They go DOWN on their own — the test fails if a file grows a new
# dead marker, and fails if a count here is too high, so a fix can't be made and
# left unrecorded.
#
# A count going UP needs a reason in the commit, and there is only one good one:
# a diagnostic that was answering the marker by accident has been removed, so a
# claim nobody was checking becomes visible. Three files went up that way when
# fixtures that had forgotten `mut` on their own locals stopped reporting
# `E0322 cannot mutate — declared let` over the rule they meant to test.
#
# Two ways off this list. Either the rule is real and the marker should fire, in
# which case the compiler needs the check (that is the interesting case — see
# audit 1.3 for two rules found unenforced this way). Or the marker is wrong and
# should go, usually because it sits below a parse error that stops the pipeline
# before the checker ever runs (see audit 1.2).
#
# Format: <file> <count of dead markers>
