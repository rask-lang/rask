# written. tests/leak_gate.sh runs every suite file under RASK_LEAK_CHECK=1,
# reports these as expected, and FAILS on a file that starts leaking without a
# line here — so the gate enforces "no NEW leaks" rather than "no leaks".
#
# When a file stops leaking, delete its line. The gate says so by name.
#

# 28 → 10, which was the per-element half of #1045), and 496 once a container

# variant, which the suite barely exercises and a decoded document is made of —,
# and 490 once a container held behind a `?` or an `or` was released with the
# value holding it, and 453 once MIR could say which container a wrapper's
# payload is (#1140), a runtime helper that uses a callback up was written down
# as not keeping it, and a container made inside one arm of a branch got a free
# where control leaves that arm (five more files clean, `t_json_decode.rk`
# 22 → 7), and 377 once one allocation under several names got freed once
# instead of not at all — twelve more files clean, and that was the whole of
# `t_week_closures.rk`, `t_week_ranges.rk` and `t_week_sorting.rk`, and 347
# once a value handed over on one path could still be released on the others —
# `try` on a `Container or E` inside a function that returns `_ or E` reads the
# error out of the wrapper and stores it into the Result going back, and the
# container on the wrapper's *ok* side went with it (`t_io_seek.rk` 21 → 0), and
# 343 once passing a trait object to a function that borrows it stopped counting
# as handing it over (`t_io_buffer.rk` 21 → 17; covering the containers inside a
# boxed value as well was tried, double-freed, and backed out — #1144), and 322
# once a `Random` had a free at all: it is a heap block behind an opaque handle
# and `rask_rng_free` did not exist, so every `Random.from_seed(n)` leaked its
# state (three more files clean), and 297 once a box gave back a container it
# holds: `Shared.mutex(Map.new())` moves the map in, so the map's free belongs
# to whoever drops the box's last reference — which only the runtime knows, so
# the payload kind travels to the constructor and lives on the box (four more
# files clean), and 287 once `Rack.snapshot()` stopped cloning a node's
# `Vec`/`Map` field twice and dropping the first copy (`p13_rack_snapshot.rk`
# 10 → 0), and 279 once a function that hands back a fresh trait box made its
# caller the owner — `return Boom.Bad` in a `-> i64 or Error` boxes the enum,
# and every failing `or Error` call leaked the box (four files improved).
#
# The rest of that one was #1147, and it is closed: 274 once a trait box got
# dropped where control leaves the region its definition rules, the same rule
# `container_drop` already uses — `classify(-1) catch e => -1` binds the error,
# so a name did own the box, but a definition inside a `catch` dominates no
# return, so it had nowhere to be dropped (`t_bare_error_type.rk` 6 → 3) — and
# 270 once the frame could follow a box through a wrapper it holds itself. A
# forwarding function reads the box out of what it called and repacks it into
# its own wrapper, and once that function is inlined the whole trip is one
# frame's: stored into an aggregate, moved with it, read out again under a new
# name. That last name owns the box (`t_any_error_boxing.rk` 4 → 2,
# `t_bare_error_type.rk` 3 → 1), and 268 once a string handed back by a trait
# call got released. MIR has three kinds of call — direct, through a closure,
# through a vtable — and the elision pass's test for "did this frame take this
# reference itself" listed only the direct one, so `n.label()` on a boxed value
# came back with a reference nobody gave back (#1145,
# `t_module_qualified_variants.rk` clean), and 250 once a closure body could
# stop being shared by two chains that disagree. Inlining copies a `flat_map`
# *create* site into each caller and leaves one body behind it, so the capture
# slot holding `f` saw the union over every closure ever passed to `flat_map`
# anywhere — one member handing back somebody else's container made the whole
# set unusable, and the chain next door leaked. Each disagreeing group of
# create sites gets its own copy of the body now (#1146,
# `t_closure_call_container.rk` 24 → 6), and 243 once one vector feeding two
# chains got one free rather than none. A capture is an escape, so the source's
# free rides along with the closure — and that counts capturers by local, so
# two inlined copies of a chain each looked like the only one and both freed
# it. Refusing both was the first answer and it leaks; the free goes after the
# last of the closure drops instead (#1148, `t42_flatten_shaped_header.rk`
# 9 → 3, `t34_vec_as_sequence.rk` clean), and 223 once a struct handed to a
# closure the frame also drops stayed the frame's. Any capture read as handing
# the aggregate away, so a sequence built over a struct's `Vec` field left the
# container to nobody — every `h.walk()` shape. The closure is a name that
# reaches the group now, the way a handle read out of one is: alive for
# placement, never the name released (`t40_forwarded_generic_method.rk`,
# `t26_custom_sequence.rk` and `t35_returned_sequence.rk` all clean), and 209
# once a closure made on one branch inside a loop got a drop at all — neither
# the back edge nor the return dominates the arm that made it, which
# `t41_closure_environment_drop.rk` had written down as unfixable and wasn't.
# The rule is `container_drop`'s and now lives in `analysis::drop_sites`,
# because three passes wanted it (`t41` clean,
# `t_closure_call_container.rk` 6 → 2), and 199 once a copy made inside a loop
# stopped counting as the end of its source. `for x in v` copies `v` into the
# body every turn, so `v` is live out of the block that copies it — reading
# that as a move left every name in the group either moved-from or with nowhere
# to put a free, and the container was freed by nobody
# (#1047, `t39_loop_backedge_container_free.rk` clean), and 185 once an
# `Atomic<T>` had a free at all. One machine word behind an opaque handle and
# no `rask_atomic_int_free` in the runtime, so every counter in every program
# leaked eight bytes — the same shape `Random` was in. It hid because
# `into_inner` reads the word and gives the block back in one call, which is
# the shape a test reaches for (`t_month_atomics.rk` and
# `t_atomic_across_tasks.rk` clean), and 180 once `os.env` stopped allocating a
# box for its answer. The runtime heap-allocated a 16-byte string header purely
# so codegen could copy out of it, and nothing freed the header — the string
# goes straight into the option's payload now (`t_os_env.rk` and
# `t_month_stdlib_modules.rk` clean), and 173 once `drop(p)` on a `Heap<T>`
# freed the block. `Heap<T>` is transparent — a reference to one has the
# payload's type, because that is what the program treats it as — so lowering
# asked "is this argument a pointer?", was told "a struct", and emitted no code
# at all. Every `Heap` of a struct leaked its block, and the one shape that
# *did* free was `Heap<i32>`, where there is no block to free
# (`p07_heap.rk` 7 → 2), and 162 once a box could hand its payload back without
# allocating a block for it. `Cell.replace` copied the old value into a fresh
# block so the pointer it returned would outlive the call, and nobody freed the
# block; `Cell.into_inner` was `Cell.get` under another name, so freeing the
# cell would have dangled that pointer and the whole cell stayed behind. Both
# write into the caller's own destination now — six more files clean,
# `t_month_boxes.rk` among them.
#
# And 155 once a string variable written every turn released what it held. By
# the time the reference-counting pass sees it the loop-carried write isn't a
# statement — it's a phi's incoming edge — and the last-use walk looks past it
# from both sides, so `mut junk = ""` rewritten eight times leaked seven
# buffers. The release goes at the end of the back-edge block, where the name
# still points at the value being replaced (`t_string_rc_escapes.rk` clean, and
# `t_vec_element_returns.rk` with it — `Vec.remove`/`Vec.pop` hand an element
# out into a name a loop then writes over, which is the same shape).
#
# And 134 once the frame owned a boxed value's contents rather than the box.
# `TraitBox` copies the value shallowly, so the box and the frame's own local
# hold the same container handle, and two boxes of one value hold it twice — a
# free has to happen exactly once, and the box is not a place where "exactly
# once" can be arranged. Calling the boxing a hand-over left the contents to
# the box's drop glue, which can't do it. `TraitDrop` is to a box what
# `ClosureDrop` is to a closure, so its presence is the answer to "does the
# frame outlive this box" (#1144, `t_io_buffer.rk` 17 → 3).
#
# Two things had to change together for that, and the first hid the second. The
# release was landing on the box's own name — `rc_dec_contents(_40)` on an
# `any Describes`, which the release walk has no case for and quietly does
# nothing about — so the container inside the boxed value leaked exactly as
# before. With the release on the value instead, the box's drop glue turned into
# a double release: it freed the value's *string* fields, right when the box was
# the owner and one decrement too many once the frame is. `TraitBox` never took
# a reference to copy, so the glue and the vtable's drop slot are gone, and a
# box dying frees its block and nothing inside it.
#
# One buffer per runtime-built element came back when a `Vec<string>` literal
# stopped taking a second reference to it. `rask_vec_from_static` is handed a
# temporary array the frame never frees, and lowering has already put a
# reference in its slots — so taking the bytes over takes the reference with
# them, and retaining on top of that leaked one buffer per element. A literal
# element carries a sentinel refcount every release walks away from, which is
# why an all-literal vector was fine and this sat unnoticed.
#
# Nine more when a container started freeing the closure blocks its elements
# point at (#1149). The element descriptor had no kind for a closure, so the
# free walk skipped it and a `Vec<func>` left one block per element. A block
# describes itself — its size and its environment-drop glue are the header words
# before the pointer — so one kind covers every closure with nothing
# type-specific to generate. The block carries a reference count now, because a
# *derived* container (clone, slice, chunk, concat) copies element bytes and two
# vectors naming one block would free it twice; a deep copy isn't available,
# since the environment's layout is known only to that generated glue and there
# is no `env_retain` to ask. `t_closure_in_collection.rk` 9 → clean.
#
# Eight more when a fused loop reading a struct field started giving the
# field's container back. `r.xs.zip(other)` reads the handle straight off the
# struct, and a bare handle is never the name a release walks — so the release
# belongs on the edge where the group dies, which is the loop's exit block.
# `aggregate_edge_releases` is that mechanism and it asked for the exit to have
# exactly one predecessor, which is the easy case of the rule it wanted. A fused
# `zip` has two ways out, one per side running out, so neither edge qualified.
# Every predecessor having it live on the way in is the same rule stated
# properly. `t_collection_api_gaps.rk` 8 → clean.
#
# Don't write the running total here. This line used to, and it drifted 22 out
# from the sum of the lines below — a fix that emptied a file removed its entry
# without touching the prose, so the tally read like a measurement and was a
# story about a state two commits back. `leak_gate.sh` prints the count and the
# file total on every run, and fails on a line whose number no longer matches
# what the file leaks, which is where that belongs.
#
# Two of the entries are `t_heap_box_dropped.rk`, written for the `drop` fix and
# left on the list because a freed box says nothing about the vector inside its
# payload — a different question from #1144's, which is about `any Trait`.
# `RASK_LEAK_TRACE=1` says which runtime function is still holding what, which
# is how each cause was found — `docs/leak-tracing.md` has the recipe.
#
# Why this file went from empty to 180 lines in one commit: the gate decided by
# grepping the output of `rask test` for the leak report, and `rask test` was
# reading the test binary's stderr and dropping it. The report never reached the
# grep, so every file read as clean. Forwarding that stderr is what made these
# visible; none of them are new (#1048).
#
# A passing `assert` on a heap string took 33 files off this list at once. The
# release was emitted on the branch that prints the strings and aborts, so the
# path that continues never ran one — every passing string assert leaked a
# buffer, and asserts are everywhere in a test suite (#1049).
#
# An adapter chain now frees the environments it built, which is most of what
# the sequence files were carrying — t41 went from 212 allocations to 12, and
# `.map()` in a loop from 200 to none (#1045).
#
# What's left, after that and after wiring Rack and Pool into the drop pass:
#   - a container captured by a closure, or nested inside another container, is
#     never freed (#1035) — the biggest remaining share. A container in a
#     *struct field* is freed now (#1120): the handle a field read hands back
#     joins the struct's value group, so liveness knows the two die together
#   - a callback that builds a value per element — flat_map's inner sequences
#     and containers — hands back something nobody owns (#1045, the half this
#     didn't reach)
#   - a closure made on one branch of an `if` has no point where freeing it is
#     unconditionally safe (#1045)
#
# Eight files came off in one go when module-level consts started being freed:
# a const has no scope to end, so the drop pass had nowhere to put a release,
# and the frees now happen in a generated `rask_const_free` the runtime calls
# after main returns and after detached tasks are awaited (#1116). That covers
# the containers and boxes a const holds, and the heap block a `string` or
# struct const's slot points at.
#
