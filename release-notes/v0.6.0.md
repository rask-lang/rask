# Rask v0.6.0

The stdlib matches its own spec. Each stdlib spec now lists what it promises
in a surface block, and a gate checks every item: declared in `stdlib/*.rk`,
public, with the spec's signature, and called by a suite program that agrees
on both backends. It started at 305 of 849. It ships at 855 of 855.

## The coverage gate

`rask stdlib-coverage` prints the gaps per module, and
`tests/stdlib_coverage_gate.sh` fails on a new one. A gap closes either way: the
stdlib gains the function, or the spec drops the promise. Both happened a lot.

The registry of known gaps, `tests/known_stdlib_gaps.txt`, is empty.

## bytes

`bytes` is a string without the UTF-8 rule: the same 16-byte value, the same
small-inline mode and refcounted buffer, the same runtime functions. A parser
can keep a packet's payload as a view into the packet, with no copy and no
reference that could dangle.

```rask
const PNG_MAGIC: bytes = x"89 50 4E 47 0D 0A 1A 0A"

let packet = buf.freeze()             // Vec<u8> → bytes, same allocation
mut r = bits.BinaryReader.new(packet)
let kind = try r.read_u8()
let payload = try r.read_bytes(len)   // a BytesView sharing packet's buffer
let text = try string.from_utf8(packet)   // checked, shares the buffer
```

`x"…"` is the one bytes literal. `b.thaw()` hands the buffer back as a
`Vec<u8>` when nothing else holds it and answers `none` when something does,
so copy-on-write is a check you write, not a hidden cost on `push`.
`string.from_utf8` takes `bytes` now; a `Vec<u8>` freezes first. `bytes`
doesn't print with `{}`; `{b:debug}` prints the literal that makes it.

A heap string's length was 32 bits; it's 62 now, with no assumption about
pointer bits. A view keeps 31 bits of start and length and panics past 2 GiB
rather than quietly copying.

## Slices are values

`s[i..j]`, `s.trim()` and the items of `s.split(…)`, `lines()` and
`split_whitespace()` are `StringSlice`s: the bytes they cover, shared with the
source, and where they sit in it ([#492], [#1633]).

```rask
for part in line.split(",") {
    let at = part.span()              // its place in line
    let keep = part.view()            // shares line's buffer, no copy
}
let name = header[0..colon].trim().view()
let parts: Vec<string> = line.split(",").to_strings()
```

Every read-only string method works on a slice, and on a `StringView`, without
copying: `s.trim().starts_with("#")`, `s[0..5] == "hello"`. Where a `string`
goes, the copy is written out: `process(s[0..5].to_string())`. Keeping a slice
is an error that names both ways to keep it: `.to_string()` copies, `.view()`
shares. `split` and friends are lazy now, each piece found as the loop asks for
it; 20,000 views of a 90 KB range take 11 MB, against 1.8 GB copied.

None of it is special to strings. `s[i..j]` is the `Slice` operator, which any
type can conform to. `@temporary` on a struct makes its values live for the
expression that makes them. `@reads_as(field)` lends a struct the read-only
methods of one of its fields, as a receiver ([specs/types/reads-as.md]).
`StringSlice` and `StringView` are ordinary structs that use them.

`split(",").to_vec()` is now `split(",").to_strings()`, which says it copies.

## One size model

`reflect.size_of`, `align_of` and `is_copy` answer on both backends ([#791]).
The Copy rule's 16-byte threshold now measures the size the value is laid out
in, padding included, so the two can't disagree. A test compiles every suite
program and example and checks that they agree.

That test caught a real bug: a struct whose field names a type declared further
down was move-only, and swapping the two declarations made it copy. Whether a
type copies no longer depends on where it's declared.

## One source per stdlib method

A stdlib function's declaration says where its body is: Rask code, `@native`,
`@builtin`, or `comptime`. Native builds its calls into the C runtime from
those declarations, checked against `rask_runtime.h`, instead of from a table
kept in step by hand ([#726]). The interpreter runs the Rask body instead of a
Rust copy of it.

Integer and float methods are declared once per family and expanded to every
width, so `u16.from_be_bytes` exists because `u64`'s does.

## New and finished modules

- New: `hex`, `base64`, `url`, `csv`, `digest`, `terminal`.
- `cli` is written in Rask and has one way in, the builder. The quick API is
  gone.
- `bits`, `io`, `fs`, `net` and `reflect` do what their specs say, on both
  backends.
- UDP sockets, with a simulated network under `rask test --sim` that loses
  datagrams. `--trace FILE` writes the schedule a seed picked.
- `os.signals` works natively.
- TLS left the stdlib. It's a package now ([specs/packages/tls.md]): it needs
  a crypto library the toolchain shouldn't carry.

## Packages

A package is described by `rask.toml`, read by a loader written in Rask against
a versioned schema. `rask add` and `rask remove` edit it, and one resolution
writes `rask.lock`. `build.rk` is only a script.

## Language changes

- Values are written in parens, braces are only for code:
  `Point(x: 1, y: 2)`.
- Named arguments go in any order. They still run in the order written.
- `x.to_string()` renders a value; `{x:debug}` prints it the way it's built.
- `reflect.size_of<[u16; 3]>()` parses. An array type as a type argument
  used to read as a comparison.
- Evaluation order is in the spec: left to right as written, receiver first.
  `v[i()] += x()` runs `i()` once ([#1524]).
- A `Vec<u8>` is a byte buffer. Containers, fields and enum payloads hold
  each value at its own width, and `T?`/`T or E` take a one-byte tag ([#985]).
- The stdlib declares its effects (`@io`, `@waits`), and the compiler infers
  them through every body. An `extern` can say `@ambient` or `@memory_only`.
- `comptime` is computed while compiling, or it's a compile error. Struct and
  enum constants fold to data.
- `int`/`uint` aliases, `Mutex<T>`, `Cell<T>` and `.lock()` are gone. Use
  `Shared<T, S>`.
- `Vec.from_raw_parts` and `cstring.from_ptr` are gone. `cstring.decode()`
  converts.

## Newly rejected

- An argument that changes what an earlier argument lent the same call.
- A left side of `=` that isn't a place.
- The stdlib's own attributes in a program.
- A result whose error union is wider than its slot.

## Fixes

Most of the work was making native agree with the interpreter on stdlib calls
it had never made: clones of optionals and tuples, default arguments inside
stdlib bodies, JSON decode of nested types, and a program function named like
a stdlib module ([#1581]). Leaks and crashes found along the way are fixed or
filed.

## Still open

- [#1218]: a rare double free with two tasks over one `Shared` plus a channel.
- [#1609]: an HTTP server in a task leaks its headers map.
- [#1628]: `HttpClient` has no way to take the TLS package, so `https://`
  fails. [#1629] says what Rask needs before it can write its own crypto.
