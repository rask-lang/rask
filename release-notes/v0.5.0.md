# Rask v0.5.0

Concurrency you can trust. A task is a fiber now, deterministic tests run on the
scheduler that ships, and a task that never waits can't keep another off its
worker.

## Fibers

A task that waits parks instead of holding a thread: join, channels, `select`,
locks, sleep and sockets. Before, a producer and a consumer on `workers: 1`
could hang ([#1353]).

Fiber stacks have a guard page, and running off one reports the task ("task 3
overflowed its stack") instead of a bare segfault.

Linux only for now. macOS still runs tasks on threads until it has a kqueue
poller.

## Preemption

```rask
while !DONE.load(SeqCst) {
    turns += 1
}
```

On one worker, that loop used to keep the task that sets `DONE` from ever
running. A task that has run past 10 ms now yields at the next function entry
or loop back edge. It costs a load per iteration.

## Sim runs the real scheduler

`rask test --sim` ([#625]) runs a test with a seeded task order, a virtual
clock, an in-memory filesystem and a loopback network, and prints a replay line
when a seed fails. It now drives the production scheduler, so what it finds is
what ships ([#1381]).

## Tasks

A task's body is a block: `spawn { work() }`, `Thread.spawn { … }`,
`ThreadPool.spawn { … }`. It runs once, so it may use up what it captures, and
its value is what `join()` hands back. `spawn(|| …)` is an error that shows the
block form ([#1318]).

Every spawn returns `Handle<T>`, and `Handles<T>` replaces `TaskGroup` and
`ThreadGroup`. `cancel()` wakes a waiting task ([#1370]).

A panic or `skip` frees what the frames it leaves own, after their `ensure`s
run. Before, a panicking task leaked everything on its stack ([#1422],
[#1518]).

## Language changes

- `own` is gone. Whether a closure outlives its frame is worked out for you
  ([#1281]).
- A closure never uses up what it captured, since nothing says how often it
  runs. What it consumes comes in as a parameter: `|take c: Conn| c.close()`
  ([#1318], [#1264]).
- Function types carry modes: `func(take Vec<i64>)`, `func(mutate Counter)`
  ([#1478]).
- Conformance is `Point implements Display { … }`. `extend T with I` is gone,
  and `trait` is `interface`.
- `.freeze()` is gone. Delete the call.
- `c is Cmd.Ins` tests a variant with a payload, like bare `c is Ins`
  ([#1401]).
- `else as e` binds what the test left over as a usable type, and works with or
  without `as` on the test ([#1454], [#1516]).
- One `eq` and one `hash` per type, used by `==`, `.hash()` and `Map` keys on
  both backends. A struct, enum, `Vec` or tuple works as a map key
  ([#1389], [#1391]).

## Newly rejected

These compiled before and were bugs waiting to happen:

- A closure holding a link or a `Local` box reaching `spawn` ([#830],
  [#1356]).
- A handle nobody joins or detaches ([#890], [#1360]).
- A `match` whose only arm for some values is guarded ([#1402]).
- Moving a value into a tuple or struct literal and using it after. Pushing or
  storing a loop element the loop only lends. Storing a field as a second owner
  (E0909, [#1459]). Clone it or take it.
- Returning a borrowed parameter, from a function or a closure (E0872, E0907).
- A type with the wrong number of type arguments (E0885), an unknown type or
  interface anywhere, a field the type doesn't declare, a type argument its
  bounds refuse.
- `<` on two `Vec`s, arrays, `Map`s or `Set`s (E0414). `for mutate` over
  something read-only (E0914).
- Calling a `private` method from outside ([#1417]).

## Fixes

A long list of native crashes, leaks and wrong answers, mostly where the
interpreter already had it right. How native decides what to free was rebuilt
on one analysis instead of four that disagreed. Every example now runs under
the leak checker. HTTP has one implementation, in Rask, on both backends
([#1378]).

## Still open

- [#1218]: a rare double free with two tasks over one `Shared` plus a channel.
  It wouldn't reproduce on demand.
