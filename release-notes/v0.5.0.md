# Rask v0.5.0

One theme: concurrency you can trust. A task is a fiber now, the deterministic
tests run on the same fiber switch and stacks that ship, and a task that computes without ever
waiting can't keep another off its worker.

The milestone was done when two numbers held in CI, and they hold:

- **The sim stress gate** runs every concurrency and panic suite file under
  `rask test --sim` over 100 seeds and finds no deadlock, race or lost panic.
- **The soak** never sees more OS threads than workers: 100k tasks, nested
  joins, `workers: 1`, panics mixed in.

## Fibers

A task that waits parks instead of holding a thread. Join, channel receive and
send, `select`, locks, sleep and sockets all park; one idle worker sleeps in
`epoll_wait` for the sockets. Before this, a worker blocked in `join` got a
replacement thread (up to 32), and a blocked receive simply kept its worker,
which is how a producer and a consumer on `workers: 1` hung ([#1353]).

Fiber stacks are mmap'd reservations with a guard page. A task that runs off
the end of one is reported by task id ("task 3 overflowed its stack") before
the process dies, instead of a bare segfault. `tests/fiber_gate.sh` checks
every callee-saved register and the float control state across a switch on x86_64 and, under
qemu, aarch64. Deleting any one register's save makes it fail.

The old stackless state-machine path had no caller left and is deleted
([#1336]).

Linux only for now. macOS still runs tasks on threads until it has a kqueue
poller.

## Preemption

```rask
func spin_until_set() -> i64 {
    mut turns: i64 = 0
    while !DONE.load(SeqCst) {
        turns += 1
    }
    return turns
}
```

Spawn that and then a task that sets `DONE`, on one worker, and without
preemption the spinner never gives the worker up. A SIGURG timer now marks a
fiber that has run past 10 ms, and every function entry and loop back edge
checks for that, so the loop above yields at its back edge. Go parks a fiber
from inside the signal handler; I check at back edges instead. It costs a load
per iteration and needs nothing from codegen but a branch.

Without the green scheduler (macOS for now) a running task holds one
of the `workers: n` slots, and preemption hands its slot to a waiting task. A
waiting task gives its slot back for the wait, the way a fiber gives back its
worker, and slots are handed out first come, first served. So a task preempted
inside a lock is harmless: whoever then blocks on the lock gives its slot back
and the owner gets one to finish in. The interpreter does the same on the same
10 ms. Under sim the budget is a number of safe points drawn from the seed, so
different seeds cut tasks off at different places and a replay cuts them off at
the same ones.

## Sim runs the scheduler that ships

`rask test --sim` ([#625]) runs a test with a seeded task order, a virtual
clock, an in-memory filesystem and a loopback network, and prints a replay line
when a seed fails. It started out passing a baton between OS threads. Now sim
plays the operating system and nothing else: the threads it switches between
(the test body, the pool workers, the green workers) are fibers on the test's
one OS thread, and tasks run on the green scheduler exactly as in production,
with its run queues, work stealing, parking and preemption ([#1381]). The
choices production leaves to timing come from the seed: which thread runs
next, which deque a steal tries, where a running task is cut off, and how many
workers a default scope gets (three or four).

Each sim test starts from fresh module state ([#1375]). Cancel wakes a task
parked on a simulated socket ([#1371]).

## One handle

`spawn`, `Thread.spawn` and `ThreadPool.spawn` all return `Handle<T>`, and one
`Handles<T>` (`new`, `add`, `join_all`, `detach`) replaces `TaskGroup` and
`ThreadGroup`. `Handles` is plain Rask, a linked list of handles. Writing it
turned up nine ownership and codegen bugs, all fixed.

`cancel()` wakes a task that is waiting ([#1370]), and `cancelled()` works: the
interpreter always said false and native couldn't compile a call to it.

## Things that are rejected now

- A closure holding a link or a `Local` box can't reach `spawn`, however it
  gets there: written in place, bound to a local, returned from a function or
  pulled out of a field ([#830], [#1356]). The last two are caught when the
  task starts, since nothing at the spawn site says what the closure captured.
  A closure built in a generic function is decided per instantiation, from
  the type, on both backends: `keep<i64>`'s crosses, `keep<Link<Node>>`'s
  doesn't, and neither does `keep(Vec<Link<Node>>.new())`'s, empty or not
  ([#1382]).
- The closure form of a blocking `Shared` read or write ([#1311]).
- A handle nobody joins or detaches ([#890], [#1360]).
- `try` in a module-level `const` ([#1339]).
- A `match` whose only arm for some values is guarded: a guard can be false,
  so a guarded arm covers nothing ([#1402]). These used to compile and stop at
  runtime with "no matching arm".

## The language moved too

- `own` is gone. The compiler works out whether a closure outlives its frame
  and captures accordingly ([#1281]).
- Conformance is `Point implements Display { … }`. `extend T with I` is gone,
  and `trait` is `interface` everywhere.
- `select` that can wait answers `T or SelectError` ([#1342]).
- `.freeze()` is gone. A `Vec` or `Map` a comptime block hands back is
  embedded as constant data with or without it, and a `const` can't change,
  so it marked nothing. Delete the call.
- `c is Cmd.Ins` tests a variant that carries a payload, the same as bare
  `c is Ins`; it was refused with "expected 1 argument" ([#1401]). Neither
  binds anything: the payload is named by writing it, `c is Ins(n)`. CF12's
  implicit unwrap, `if c is Ins { c + 1 }`, is deleted from the spec; nothing
  ever implemented it.

## Other fixes

A deadlock is reported instead of hanging ([#1354]). An unbuffered channel with
two senders lost a handoff ([#1345]). A `Shared` holding a `Shared` leaked the
inner box ([#1302]), and a `Vec<T or E>` leaked each error's payload ([#1357]).
A whole-value write through `with box.write() as p` didn't replace what the box
held on native. A user function named like a private stdlib helper replaced it
inside the stdlib ([#1351]).

A loop that rebuilds a value from itself, `left = Expr.Binary(left: left, …)`,
released the old `left` at the top of each turn: stack garbage the first time
round, a double release after. `examples/cli_calculator.rk` had it and got
lucky until preemption moved its stack frame.

Native `conn.read_http_request()` handed back every request with an empty url
and a cut-off one as a blank `GET /` ([#1377]). And the interpreter answered
all of HTTP from a Rust copy of its own, which drifted three times in a week
([#1378]). There's one implementation now: both backends run `stdlib/http.rk`,
message framing included, over a single "read what's there" socket primitive.
A response carries its headers, and `IoError.last_os_error()` works on the
interpreter.

How native decides what to free was rebuilt. The release passes (refcounts,
containers, interface boxes, closures) used to group every name for one value
and then patch the cases where the grouping was wrong, and each patch was a
rule on top of a wrong shape. All four now share one analysis that tracks, path by path, whether a value is still the frame's
and which name certainly holds it, and release it where it stops being needed
on every path that meets. Four leaks went with the old shape: a `take self`
method that turned one enum into another, handing a payload back on one arm
and building a new value on the other ([#1383]); a `Vec` read through a fused
adapter both inside a loop and after it ([#1384]); a `Vec` behind an optional
tag ([#1305]); and the error's message in a match over `Vec<T> or E`
([#1338]).

## One `==`, one `hash`

A type's equality and hash used to live in three places that disagreed. Native
compared struct fields in place and hashed map keys as raw bytes, the
interpreter compared keys structurally, and neither asked a type's own
`implements Equal`.

```rask
let a = Name { first: long.to_lowercase(), n: 1 }   // a heap string
m.insert(a, 1)
m.contains(b)              // native: false, now true
[1, 2] == [1, 2]           // native: false, now true
(Version { major: 1, minor: 0 }, 2) == (Version { major: 1, minor: 5 }, 2)
                           // ignored Version's own eq; now uses it
```

Now there's one `eq` and one `hash` per type, and `==`, `.hash()` and a `Map`
key all call it on both backends ([#1389], [#1391]). Derived ones are written
by the checker from the field types. Tuples, `T?` and `T or E` compare part by
part through each part's own `eq` ([#1392]). A struct, enum, `Vec` or tuple
works as a map key, including one holding heap strings.

An optional compares with a bare value either way round, `opt == v` or
`v == opt`, through the payload's `eq`.

## Ownership the checker now enforces

Two rules were in the spec and not checked. They are now, so code that relied
on the gap stops compiling:

```rask
let t = (v, 1)
v.len()                    // error: `v` moved into the tuple

for g in groups {
    out.push(g)            // error E0902: the loop only lends `g`
}
```

Storing a value in a struct, tuple or array literal moves it, the same as
assigning it does. A loop over a `Vec`, `Map` or array lends each element, so
the element can't be pushed, stored or bound to a new name. Clone it, or loop
over `take_all()` to take the elements out. Both holes were double frees
waiting for a container that freed what it held.

That makes a generic function storing a borrowed `T` an error too, the same as
pushing one already was. Say `take value: T`, or bound it: `T: Copy` now works,
holds for a type whose values copy, and is checked at the call:

```rask
func wrap<T: Copy>(value: T) -> Wrapper<T> {
    return Wrapper { value }
}
wrap(3)                    // ok
wrap(v)                    // error: `Vec<i64>` isn't Copy
```

## Native memory, continued

A tuple frees what it holds: a `Vec` inside a tuple local, and the strings in a
`Vec<(string, i64)>` or a tuple map key, all leaked ([#1395]). A struct passed
to a method that only reads it, like `m.get(k)`, was treated as given away and
leaked its strings ([#1394]). Whether a call keeps an argument is now read off
the callee's declaration for every argument, with the runtime's own helpers
listed the same way. `.clone()` on an enum segfaulted natively when the
variant's payload was a scalar that looked like another variant's tag.

The examples gate runs every example under the leak checker now ([#1379]).
Six examples leaked with every answer right: `cli.args()` was never freed, nor
a struct field written over, nor a value taken out of a `mutate self` field
with `take`, nor a string whose last use came after a `continue`, nor a match
result from an inlined method. A comptime `Vec<bool>` read back eight flags as
one, so `FLAGS[i] == true` was false.

A `match` guard that fails tries the arms below it. Natively it skipped a later
arm for the same variant and returned nothing, and a guard on a string or
`T? or E` match was ignored. A match that no arm takes panics on both backends.
