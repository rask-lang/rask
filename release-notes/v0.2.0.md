# Rask v0.2.0

First release where the downloaded binary can actually compile a program.

## The reason this release exists

`v0.1.1`'s binary couldn't build anything. The compiler links a C runtime, and
it found that runtime by walking up from its own path looking for
`compiler/runtime/` — which exists in a checkout and nowhere else. So
`rask run hello.rk` on a downloaded `rask` ended at:

```
error: link: Could not find runtime directory — set RASK_RUNTIME_DIR to the
directory containing runtime.c
```

Everything that doesn't link worked (`--interp`, `check`, `fmt`); everything
that does — `run`, `build`, `compile`, `test`, which is the point of the thing —
did not. The runtime sources now travel inside the binary and are unpacked to
the cache on first use. A checkout on disk still wins, so editing
`runtime/*.c` takes effect on the next compile without rebuilding the compiler.

`rask --version` also reports the version now. It said `0.1.0` under the
`v0.1.1` tag, because the tag and the workspace version were never connected.

## What's in it

All five validation programs compile and run natively: an HTTP JSON API server,
a grep clone, a game loop with entities, a text editor with undo, and an
embedded sensor processor. Each is enrolled in a gate with its output diffed on
both backends, so this is measured on every push rather than asserted here.

- **140 specs**, 29 stdlib modules, 234 error codes, 458 suite programs.
- **Eleven CI gates.** The two backends (interpreter and Cranelift native) are
  run against each other on every suite program — 450 agree, 8 are registered
  red with an issue each. Two of those 8 are bugs; the other 6 are features
  that aren't built yet.
- **A leak gate.** Every suite program runs under leak checking, and a program
  that starts leaking without a registry line fails the build.
- **Multi-package builds.** `rask build` across a package boundary had no test
  coverage until this cycle and did not work; there are eleven fixtures and a
  gate now.
- Valgrind reports **0 errors across 283 suite and example binaries**.

## Known gaps

Not fixed, tracked, and worth knowing before you file:

- **151 programs still leak.** The leak gate enforces "no new leaks", not "no
  leaks". Most of what's left is one question — a container that crossed into
  or out of another value is freed by nobody ([#1035], [#1117]).
- **Ranges have no methods** beyond `for` — no `.map()`, `.sum()`, `.to_vec()`
  ([#920]). `Vec.iter()` adapters do work.
- **Eleven declared Vec/Map methods are unimplemented** on both backends —
  capacity control, `get_clone`, `remove_where` ([#912]).
- **No SIMD below the type checker** ([#1059]); `@binary` generates no methods
  natively ([#1058]).
- **`os.Command` is interpreter-only** ([#856]).
- Cross-compilation configures a target but needs a C cross-linker; `--target`
  and `rask targets` work, the wider toolchain doesn't.
- Incremental compilation is designed, not built. `rask build` caches object
  files but doesn't patch at function granularity.

## Platforms

Linux x86_64 and macOS aarch64. Both need a C compiler on the machine — the
runtime is compiled and linked locally, which is also why the sources ship
inside the binary.

## Note on the commit range

`v0.1.1` shares no ancestry with this release; the history was replaced between
them. GitHub's compare view for the two tags is not a diff of this release, and
a generated commit list would be every commit on `main` rather than the new
ones. Roughly 184 issues were closed in the span.
