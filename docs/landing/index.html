A systems language without the bookkeeping

Rask compiles to native code, has no garbage collector, and has no lifetime annotations. You write the program; the compiler works out who owns what.

Somewhere between Rust and Go. Closer to Rust on safety, closer to Go on how much you have to write down.

Why another language

I got frustrated. Rust has genuinely good ideas and I use them, but a lot of my day goes on satisfying the borrow checker rather than on the problem I sat down with. The alternative is a language with a garbage collector, where you stop thinking about memory by giving up control of it.

There is a gap between those two, and I wanted something in it: no collector, no pauses, and no lifetime annotations either.

Whether that gap can actually be filled is the open question. Rask is me trying to answer it by building the thing.

What’s different about it

One rule, and most of the language follows from it: a reference can’t be stored.

You can borrow a value for a call or an expression. You cannot put the borrow in a struct field, and you cannot return it.

That sounds like a restriction, and it is. What you get for it: nothing outlives the thing it points at, so there is nothing for the compiler to track and nothing for you to annotate. Signatures carry types and stop there.

The other rules — values move, files get closed exactly once, graphs live in a rack — are consequences. The book takes them one at a time.

The program at the top of this page is the same idea doing real work. fs.open hands back a file the compiler makes you close exactly once, ensure schedules that for the end of the scope, and try returns early on failure — and leaving early still closes the file, because the close was already booked. Three separate rules; the idiom falls out of them meeting.

What it costs

If you want pointer-level control over layout and traversal, use Rust or C++. Rask doesn’t offer it.

You give up

  • References in struct fields
  • Returning a reference from a function
  • Implicit copies of anything large
  • Pointer-chasing a graph you built by hand

You get

  • No lifetime annotations, anywhere
  • Signatures you read in one pass
  • Allocations visible at the call site
  • Deterministic cleanup, no GC pauses

Strings are the exception I made deliberately: string is immutable and refcounted, so it passes around like an integer and never needs .clone(). The visible cost is for the things that really do own heap memory.

Where it actually stands

Measured 2026-09-12 by running it. This section gets re-measured, not copy-pasted.

Runs today

  • Native codegen via Cranelift, plus an interpreter that acts as the reference for what the answer should be
  • Ownership, moves, borrows, linear resources
  • Rack and Link for graphs, on both backends
  • Structs, enums, generics, traits, comptime
  • spawn/join, channels, thread pools
  • Packages, workspaces, watch mode, LSP

Not there yet

  • No fibers. spawn is an OS thread; the M:N scheduler is designed, not built
  • Panics abort instead of unwinding
  • x86-64 only, and SIMD is a stub

Caveats

  • Around 80 open issues, most of them codegen getting memory release wrong
  • It’s a solo project, so fixes land in waves
  • Pre-0.1: breaking changes whenever a design turns out wrong

There are five test programs: a sensor processor, a grep clone, a game loop with entities, a text editor with undo, and an HTTP JSON API server. All five run natively. The HTTP one started working last week, once a bug that corrupted the first eight bytes of every response was fixed. They live in examples/ and CI runs them.

Should you learn it?

Not if you need to ship something next month. It’s pre-0.1 and a solo project, the ecosystem is what you see in this repository, and breaking changes land whenever a design turns out wrong. Go or Rust will serve you better and it isn’t close.

Worth an hour if you’ve hit the wall it’s built for: you wanted the safety without the annotations, or you tried to write a graph in Rust and gave up, or you keep reaching for a garbage collector you don’t really want. The playground is the cheapest way to find out — nothing to install, and half an hour tells you whether the trade suits how you think.

Ideas and complaints are both welcome on GitHub issues, and the blog has the longer argument.
