# Notes

Longer pieces about why Rask is shaped the way it is. Each one is dated and
left as written — where a decision has since changed, there's a note saying so
rather than a quiet edit.

- [Why a new language?](why-a-new-language.md) — the gap I think exists, and the
  one structural bet that tries to fill it.
- [The soul of Rask](the-soul-of-rask.md) — transparency, structural safety and
  pragmatism, and what happens when they disagree.

For the reasoning behind a specific rule, the
[specs](https://github.com/rask-lang/rask/tree/main/specs) carry it inline;
[RULINGS.md](https://github.com/rask-lang/rask/blob/main/specs/RULINGS.md) is
how open questions get settled.
