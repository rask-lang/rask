# Contributing

The most useful thing to do with Rask right now is use it and say where it
breaks: a program that crashes, an error message that left you guessing, a
page in this book that says something the compiler doesn't do.
[Open an issue](https://github.com/rask-lang/rask/issues/new) with the smallest
program that shows it, what it printed, and `rask --version`.

[CONTRIBUTING.md](https://github.com/rask-lang/rask/blob/main/CONTRIBUTING.md)
in the repository covers the rest: building from source, running the tests,
which checks CI runs, and where things are.

The two pages here are about the design and the book:

- [Design process](design-process.md): the principles every feature is
  measured against.
- [How this book is built](how-this-book-is-built.md): the rules for adding a
  page or a tour step, and why every block in it is checked.
